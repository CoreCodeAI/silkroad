# P2 客服与售后：功能需求

净室说明：本文只描述场景、行为、数据和人工确认点，用我们自己的话写成。写 skill 时只能参考本文、`docs/vendors/` 下的供应商公开资料和本仓库已有代码。

## 可用的数据和工具

| 来源 | 工具 | 说明 |
|---|---|---|
| 本地知识库 | `silkroad_knowledge` | 列出或搜索 `~/SilkRoad/knowledge/` 下的商品资料（products/）、售后规则（policies/）、认可的回复示例（replies/）。找到文件后用文件工具读全文 |
| 用户自己的 TikTok Shop | `silkroad_tts_messages` | 买家会话列表、某个会话的消息（只读） |
| | `silkroad_tts_orders` | 订单详情（用订单号查）或按状态、时间搜索 |
| | `silkroad_tts_returns` | 退货退款申请 |
| | `silkroad_tts_products` | 自己店铺的商品详情 |
| FastMoss | `product_review_list` | 任意商品（自己的或竞品）的买家评论 |
| | `product_detail_info` | 商品评分、基础信息 |
| 用户上传 | 文件 | 用户从 Seller Center 导出的评论或聊天记录（CSV/Excel 转 CSV），或直接粘贴到对话里的文本 |

所有 TikTok Shop 工具都是只读的：**SilkRoad 不替用户发消息、不处理退款**。智能体起草，用户在 Seller Center 里自己发送和操作。

## S7 买家消息多语言回复起草 `tiktok-buyer-reply`

**场景**：卖家每天要回复不同国家买家的消息（物流、尺码、使用问题、退货、投诉），语言不通、规则记不全，回复慢会影响店铺评分。

**输入**
- 必需：买家消息。来源三选一：用户粘贴的原文；`silkroad_tts_messages` 读到的会话；用户指定的会话 ID。
- 可选：订单号（没有时尝试从会话里找）、回复语气偏好、是否批量处理所有未回复会话。

**行为**
1. 识别买家语言、意图（物流查询、尺码/使用咨询、质量问题、想退货退款、催发货、投诉威胁差评、其他）和情绪强弱。
2. 给用户一句中文摘要：买家是谁、要什么、情绪如何、订单当前状态。
3. 查依据：
   - 订单状态、物流、金额：`silkroad_tts_orders`；退货进度：`silkroad_tts_returns`。
   - 商品事实：知识库 products/，其次 `silkroad_tts_products`。
   - 能承诺什么：知识库 policies/。规则里没写的承诺（赔偿金额、补发、额外折扣）不能写进回复，要列为待用户决定。
4. 用买家的语言起草回复，同时附一份中文对照。语气礼貌、简短、先回应情绪再给方案；不要承诺规则之外的东西；不要引导站外交易或留联系方式（平台禁止）。
5. 批量模式：逐个会话输出「摘要 + 草稿 + 待决定事项」，按紧急程度排序（投诉和差评威胁最前）。

**输出**
- 每条消息：中文摘要、意图和紧急程度、依据（订单状态、引用的规则文件和条目）、买家语言的回复草稿、中文对照、需要用户决定的事项。
- 知识库里缺失、导致无法确定回复的规则，单独列出来，建议补进哪个文件。

**人工确认**
- 所有回复都只是草稿，由用户自己在 Seller Center 发送。
- 涉及退款、补发、赔偿、例外处理的，必须用户拍板。
- 涉及人身安全、法律威胁、平台投诉的，提醒用户人工处理。

## S8 评论和差评洞察 `tiktok-review-insights`

**场景**：卖家想知道买家对自己商品（或竞品）满意和不满意的地方，用来改产品、改 Listing、改客服话术，以及决定差评怎么回应。

**输入**
- 必需：商品（自己店铺的商品 ID/链接，或竞品商品 ID/链接），或用户导出的评论文件。
- 可选：对比的竞品（1 到 3 个）、时间范围、只看差评（1-3 星）。

**行为**
1. 拉取评论：FastMoss `product_review_list`（分页，尽量覆盖足够样本），或读用户文件。记录样本量和时间范围。
2. 多语言评论统一理解后归类：
   - 好评主题：买家最喜欢什么（作为 Listing 卖点的证据）。
   - 差评主题：质量、尺码/规格不符、和描述不符、物流破损、慢、使用困难、性价比等；每个主题给出现次数、占比、代表性原话（保留原语言并附中文翻译）。
3. 区分根因：产品问题、描述问题（期望管理）、物流问题、客服问题。
4. 有竞品时做对比：同一主题在各商品中的占比，找出对手的短板就是我们的机会。
5. 建议：
   - 产品和供应链改进（给采购/工厂的具体修改点）。
   - Listing 修改（补充说明、尺码表、图片要展示什么）——可交给 `tiktok-listing-seo`。
   - 客服话术：针对高频差评的标准回复草稿，可存入知识库 replies/。
   - 对具体差评的公开回复草稿（用评论的语言）。

**输出**
- 样本说明（数量、时间、星级分布）。
- 好评主题表、差评主题表（次数、占比、原话示例）。
- 根因分析和按影响排序的改进清单。
- 可选：竞品对比表、回复话术草稿。

**人工确认**
- 样本少于 30 条时明确提示结论不可靠。
- 公开回复差评由用户确认后自己发布。
- 不建议任何诱导好评或删除差评的做法（违反平台规则）。

## 知识库约定

- 默认位置 `~/SilkRoad/knowledge/`，第一次使用时自动创建 README 和示例规则。
- 商品资料：`products/<商品名或SKU>.md`，写卖点、规格、尺寸、材质、包装、常见问题、禁止的宣称。
- 售后规则：`policies/*.md`，写退换货时限、运费承担、补发、赔偿上限、必须转人工的情况。
- 回复示例：`replies/*.md`，用户认可的话术。
- 智能体只读不写；需要补充的内容以建议形式交给用户（用户同意后可以由智能体写入）。
- 文件太多（例如超过几百个、搜索结果经常截断）时再考虑向量检索。
