# P1 功能需求表：TikTok Shop 上新与内容

净室规则见 [../cleanroom.md](../cleanroom.md)。本表只写场景、行为、数据和人工确认点，是写 skill 的唯一业务依据。

## 通用约定（所有场景都适用）

- **市场**：每个任务开始前确认目标站点（如 US、GB、ID、TH、MY、VN、PH、SG、MX 等）。用户没说就问，不要默认。
- **数据真实性**：所有数字都要来自工具结果，并写明来源工具和时间范围。没有数据的地方写"没有数据"，不要估算填空。推断要明确标成推断。
- **数据源可用性**：开始前调用 `silkroad_status`。FastMoss 没连上时，告诉用户这个场景需要它，并说明怎么连；只用其他数据源能做的部分照常做，同时说明缺了什么。
- **成本意识**：FastMoss 按调用计费。每个场景先做少量关键查询，给出初步结论，再问用户要不要深挖。可以用 `mcp__fastmoss__credit_usage_summary` 查剩余额度。
- **类目 ID**：用户说的是类目名称时，先用 `mcp__fastmoss__search_category_by_words` 换成类目 ID。
- **不编造**：不编造商品参数、认证、材质、功效、用户评价。用户没给的事实就问。
- **交付**：结论在前，证据在后；表格优先；最后给出"建议下一步"。

工具名写法：FastMoss 工具在对话里是 `mcp__fastmoss__<工具名>`；SerpApi 是 `silkroad_serpapi_search`；通用搜索是 `silkroad_web_search`；图片生成是 `silkroad_generate_image`。

## S1 选品调研 `tiktok-product-research`

**场景**：卖家有一个商品想法（一个关键词、一个品类或一个竞品链接），想知道值不值得在某个站点上测试。

**输入**
- 必需：商品方向（关键词、品类名或竞品商品链接/ID）、目标站点。
- 可选：目标售价区间、采购成本、自身优势（货源、品牌、内容能力）。

**输出**
1. 结论：值得测 / 小批量试 / 暂缓，一句话理由。
2. 需求：品类销量和 GMV 趋势（近 7/28/90 天）、站外搜索热度趋势。
3. 竞争：头部商品和店铺的集中度、新品能不能冲上来、价格带分布。
4. 内容依赖：销量主要来自短视频、直播还是商品卡；需要什么量级的达人。
5. 买家痛点：竞品差评里反复出现的问题，可作为差异化方向。
6. 风险：季节性、合规（如电池、液体、儿童用品、医疗宣称）、物流。
7. 建议下一步：如果要测，测什么价格、找什么达人、准备什么内容。

**数据**
| 需要 | 工具 |
|---|---|
| 类目 ID | `search_category_by_words`、`product_category_info` |
| 品类规模、趋势、价格分布 | `market_category_analysis`（basic_metrics / sales_trends / price_distribution） |
| 品类排名与集中度 | `market_category_ranking` |
| 达人层级与销量关系 | `market_category_author_sales_matrix` |
| 头部商品 | `product_rank_top_selling`、`product_search` |
| 新品机会 | `product_rank_new_listed` |
| 单品销量趋势与渠道 | `product_sales_trend`、`product_overview` |
| 买家痛点 | `product_review_list` |
| 站外搜索热度 | `silkroad_serpapi_search`（engine=google_trends） |
| 合规与政策 | `silkroad_web_search`、`search_fastmoss_documents` |

**人工确认**
- 开始前确认站点和类目范围。
- 初步结论后问是否深挖（深挖会消耗更多额度）。
- 最终是否测品由用户决定。

## S2 市场机会评估 `tiktok-market-opportunity`

**场景**：卖家还没有具体商品，想在一个站点里找值得进入的品类或细分方向；或比较几个品类/站点。

**输入**
- 必需：站点（一个或几个）、候选品类（一个或几个，也可以是一级类目让工具往下找）。
- 可选：时间窗口（默认近 28 天）、资金和团队规模（影响推荐）。

**输出**
1. 机会评分表：每个候选一行，列包括增长率、市场规模、头部集中度、新品占比、平均价格、内容渠道结构、达人门槛。评分规则写在表下面。
2. 推荐的 1–3 个细分方向，各自的切入理由和主要风险。
3. 每个推荐方向的代表商品（3–5 个）作为参考。
4. 建议下一步：对推荐方向做 S1 选品调研。

**数据**
| 需要 | 工具 |
|---|---|
| 品类指标与趋势 | `market_category_analysis`、`market_category_ranking` |
| 子类目结构 | `product_category_info` |
| 达人门槛 | `market_category_author_sales_matrix` |
| 新品成功率 | `product_rank_new_listed` |
| 头部店铺 | `shop_rank_top_selling` |
| 内容热度 | `video_search` |

**人工确认**
- 确认评估范围（站点、品类、时间窗口）。
- 评分权重可以让用户调整（例如更看重低竞争还是大市场）。

## S3 Listing SEO：标题与描述 `tiktok-listing-seo`

**场景**：为一个已上架或准备上架的 TikTok Shop 商品写或改标题、描述和关键词。

**输入**
- 必需：商品事实（名称、规格、材质、尺寸、颜色、数量、适用人群、核心卖点）或已上架的商品链接/ID；目标站点和语言。
- 可选：品牌名、不能使用的词、想要的风格。

**输出**
1. 关键词表：核心词、属性词、场景词、长尾词，每个词注明来源（竞品标题、站外搜索、买家评价用语）。
2. 标题方案 3 个：各自的侧重（搜索覆盖 / 点击吸引 / 简洁），标注字符数。
3. 商品描述：按"卖点 → 规格参数 → 使用场景 → 包装清单 → 售后说明"组织，用目标站点语言。
4. 属性填写建议（类目属性）。
5. 合规检查：标出可能违规的说法（绝对化用语、医疗/功效宣称、未经证实的认证、侵权品牌词）。
6. 和当前版本的对比（如果是改写）。

**数据**
| 需要 | 工具 |
|---|---|
| 自家或竞品商品详情 | `product_detail_info` |
| 同类头部商品标题 | `product_search`、`product_rank_top_selling` |
| 买家常用语、关注点 | `product_review_list` |
| 站外搜索词 | `silkroad_serpapi_search`（google / google_trends） |
| 平台规则 | `search_fastmoss_documents`、`silkroad_web_search` |

**人工确认**
- 商品事实必须由用户确认；缺失的参数就问，不能补写。
- 最终文案由用户确认后才算完成。
- 平台字数限制和规则以 TikTok Shop 当前官方规则为准；不确定时提示用户核对。

## S4 定价策略 `tiktok-pricing-strategy`

**场景**：给一个商品定上架价、活动价，并检查利润是否撑得住达人佣金和广告。

**输入**
- 必需：商品（链接/ID 或描述）、站点、单件到手成本（采购 + 头程 + 包装）。
- 可选：尾程/履约费、平台佣金率、支付手续费、目标毛利率、计划达人佣金率、广告预算、退货率。缺的费率要问用户，或标明是假设值。

**输出**
1. 竞品价格带：同类商品价格分布、头部商品的价格和销量。
2. 竞品佣金：同类商品给达人的佣金率范围。
3. 利润测算表：在 3–5 个候选价格下，逐项列出收入、各项费用、达人佣金、广告分摊、净利润和毛利率。
4. 推荐价格：上架价、首发活动价、长期价，以及推荐理由。
5. 盈亏平衡点：最低可接受价格、最高可承受佣金率。
6. 测价计划：先用什么价格测、看哪些指标、什么情况下调整。

**数据**
| 需要 | 工具 |
|---|---|
| 价格分布 | `market_category_analysis`（price_distribution）、`product_search`（价格区间筛选） |
| 竞品详情与 SKU | `product_detail_info`、`product_sku` |
| 竞品达人与佣金 | `product_creator_analysis` |
| 竞品广告投入 | `product_investment` |

**人工确认**
- 成本和费率必须来自用户或官方来源；假设值要醒目标注。
- 推荐价格由用户最终决定。

## S5 主图与详情图 `tiktok-product-images`

**场景**：为商品做 TikTok Shop 商品卡主图（1:1）和详情页图，可以只出方案和提示词，也可以直接生成图片。

**输入**
- 必需：商品事实和卖点、目标站点。
- 强烈建议：用户提供的商品实拍图（文件路径）。没有实拍图时只能生成概念图，必须告知用户不能当作实物图使用。
- 可选：品牌色、风格偏好、想突出的卖点顺序。

**输出**
1. 图片规划：主图 1 张 + 副图若干，每张写清楚目的（展示外观 / 讲一个卖点 / 尺寸对比 / 使用场景 / 包装清单）。
2. 每张图的画面说明和生成提示词（英文提示词 + 中文说明），图上文字用目标站点语言。
3. 竞品视觉对标：头部竞品主图的共性与可以差异化的地方。
4. 生成结果（当图片生成已配置时）：保存路径，以及逐张检查结论（商品外观是否和实拍一致、文字是否清楚、有没有平台禁止的元素）。

**数据**
| 需要 | 工具 |
|---|---|
| 竞品主图 | `product_detail_info`、`product_rank_top_selling` |
| 买家关注点（决定卖点顺序） | `product_review_list` |
| 生成图片 | `silkroad_generate_image`（需用户在面板配置图片生成服务） |

**人工确认**
- 先给图片规划，用户确认后再生成（生成要花钱）。
- 用户从生成结果里挑选；不合格的可以重做。
- 图片里不能出现他人商标、伪造的认证标志、虚假的效果对比。

## S6 短视频脚本 `tiktok-video-script`

**场景**：为商品写 TikTok 带货短视频脚本，供自己拍或交给达人。

**输入**
- 必需：商品（链接/ID 或卖点描述）、目标站点和语言。
- 可选：时长（15 / 30 / 60 秒）、形式（口播、开箱、演示、对比、剧情）、出镜人设、是否用于广告投放。

**输出**
1. 爆款参考：同类商品热门视频的共性（开头方式、结构、时长、卖点顺序），附视频数据。只提炼结构，不照搬别人的台词。
2. 脚本 2–3 版：每版包括开头 3 秒钩子、分镜表（时间、画面、口播、屏幕文字）、结尾行动号召。
3. 发布文案和话题标签建议。
4. 拍摄清单：需要的道具、场景、镜头。

**数据**
| 需要 | 工具 |
|---|---|
| 商品卖点 | `product_detail_info`、`product_review_list` |
| 带货视频 | `product_video_list`、`video_search` |
| 视频表现与趋势 | `video_detail_analysis`、`video_data_trends` |
| 视频口播结构 | `video_script_info` |

**人工确认**
- 卖点和宣称由用户确认，不能写夸大或无法证实的效果。
- 用户选定脚本版本后再细化。

## 角色与团队（P1 第 3 步）

| 角色 | 负责场景 | 说明 |
|---|---|---|
| 选品专家 | S1、S2 | 只做判断和证据，不写文案 |
| Listing 优化师 | S3、S5、S6 | 文案、图片、视频脚本 |
| 定价策略师 | S4 | 价格与利润 |
| 运营总监 | 统筹 | 拆解任务、分派给上面三位、汇总成上新方案，所有需要用户拍板的事集中问 |

团队「TikTok 新品上新」：运营总监 + 选品专家 + Listing 优化师 + 定价策略师。典型流程：选品专家确认值得做 → 定价策略师定价 → Listing 优化师出标题描述、图片方案、视频脚本 → 运营总监汇总成一页上新方案。
