# TikTok Shop 短视频脚本

> **TikTok 数据来源**：下文写的是 FastMoss 工具。`silkroad_status` 显示 FastMoss 没连上、Kalodata 为 `configured` 时，改用 Kalodata：按 `kalodata-data` 技能第 5 节的对照把每一步换成 `silkroad_kalodata_*` 工具，费用控制和口径照那个技能；Kalodata 没有对应的数据写"没有数据（Kalodata 不提供）"。两个都连上时默认用 FastMoss，用户指定时听用户的；两个都没有时才按本技能的降级方式处理。

为商品写 TikTok 带货短视频脚本，供自己拍或交给达人。从同类爆款视频学结构（开头方式、节奏、卖点顺序），但不照搬别人的台词、画面或镜头序列。

## 0. 确认输入

- **必需**：商品（链接/ID，或用户写的卖点描述）；目标站点和语言。
- **可选**：时长（15 / 30 / 60 秒，默认 30 秒）；形式（口播、开箱、演示、对比、剧情）；出镜人设（本人、达人、无出镜）；是否用于广告投放。
- **必须用户确认**：卖点和可宣称的范围。没确认的效果不能写进脚本。

如果用于广告投放，额外确认：出镜人授权、背景音乐和素材版权、可以提供的证据。广告规则以 TikTok 当前官方规则为准。

## 1. 检查数据源

调用 `silkroad_status`。

- FastMoss 未 connected：脚本仍可写，但"爆款参考"一节写"没有数据（FastMoss 未连接）"。告诉用户连接后可以补充同类视频结构。不要凭印象说"同类热门视频通常都是……"。
- FastMoss 已 connected：按第 2 节分阶段取数。

## 2. 爆款参考（分阶段取数）

FastMoss 按调用计费。每一步之后先给初步结论，再决定要不要下一步。

第一轮（约 3 次调用）：

1. `mcp__fastmoss__product_detail_info`：拿商品卖点、价格、类目。用户已给卖点描述时可跳过。
2. `mcp__fastmoss__product_video_list`：查带这个商品的视频，取一页（10–20 条）。如果是找同类视频，改用 `mcp__fastmoss__video_search` 按关键词或类目搜索。
3. 从结果里挑 3–5 条与商品最相关、表现最好的视频，逐条调用 `mcp__fastmoss__video_detail_analysis`，看播放、互动、关联商品和时长。

第二轮（先问用户，同意后再做）：

4. 对其中 2–3 条最好的视频，调用 `mcp__fastmoss__video_data_trends`（播放趋势）和 `mcp__fastmoss__video_script_info`（字幕或口播文本）。
5. `mcp__fastmoss__product_review_list`：取买家关注点，用来排卖点顺序。

工具参数名（`filter.*`、`video_id`、`page`、`pagesize` 等）以连接后实际返回的 schema 为准。

### 提炼结构，不抄台词

只记录结构，不记录原句：

| 视频 | 播放 | 点赞 / 评论 / 分享 | 时长 | 开头方式 | 结构 | 卖点顺序 | 数据来源与时间 |
|---|---|---|---|---|---|---|---|

- **开头方式**用类型描述：提问、冲突、结果先给、反常识、场景切入、直接展示产品。
- **结构**用骨架描述：问题 → 方案 → 证据 → 行动号召，或者 演示 → 对比 → 价格 → 行动号召。
- **口播节奏**：可以估算"每秒字数"，但要标明"估算"。
- 不得逐句翻译、改写或保留别人的口播、字幕、梗、音乐段落的安排细节。在输出中写"开头用了结果先给的结构"，不写"他说了……"。
- 没有数据的指标写"没有数据"，不估算。

## 3. 脚本 2–3 版

每版使用不同的结构，避免只改几个词：

- **版本 A：痛点开场**。问题 → 产品解决 → 演示证据 → 行动号召。
- **版本 B：结果先给或真实对比**。先给一个可验证的结果画面，再讲过程。对比必须真实可复现，不能夸大。
- **版本 C：场景代入**。一个具体生活场景，产品自然出现，口播少。

每版都写：

- 时长、出镜人设、卖点顺序。
- **开头 3 秒钩子**：画面、口播（站点语言）、屏幕文字。
- **分镜表**：

| 时间 | 画面 | 口播（站点语言） | 屏幕文字 | 镜头与道具 |
|---|---|---|---|---|
| 0–3s | | | | |

- **结尾行动号召**：引导去商品卡，按平台当前界面文案表述，不要写死按钮名称。

镜头数参考（经验值，仅作规划参考）：

- 15 秒：约 3–4 个镜头
- 30 秒：约 5–7 个镜头
- 60 秒：约 8–12 个镜头

口播字数按语速估算，并标注"估算"。

脚本规则：

- 每个卖点后面都要有证据画面（实物、演示、尺寸参照、使用过程），不能只靠口播说。
- 只用用户确认的卖点。不说"治愈""根治""最有效""100%"等词。
- 价格、优惠、库存只用用户给的信息。活动未确认就不写。
- 演示危险品（电池、液体、刀具）、儿童用品、食品、化妆品时，写明安全画面，并提醒用户检查合规要求。

## 4. 发布文案与话题标签

- 文案 1–2 句，站点语言，不写未证实的效果。
- 话题标签 3–5 个：商品品类词 + 场景词 + 1–2 个从工具结果里看到的标签（`video_search` 或商品视频的标签字段）。标注来源。
- 不承诺会上热门或某个播放量。

## 5. 拍摄清单

| 类别 | 项目 | 数量 | 备注 |
|---|---|---|---|
| 道具 | 实物样品 | | 必须是售卖版本，演示用的样品与上架一致 |
| 场景 | | | |
| 镜头 | 近景、特写、俯拍、手持等 | | 每个镜头对应分镜表的编号 |
| 灯光与收音 | | | |
| 字幕 | 字体、位置、字数 | | 字幕文字与口播一致 |
| 画幅 | 竖屏为常见做法 | | 具体以 TikTok 当前规则为准 |

## 6. 合规检查

每版脚本发给用户前过一遍：

| 检查项 | 说明 |
|---|---|
| 功效或医疗宣称 | 治疗、消炎、减肥、美白效果等，删除或替换为外观和使用描述 |
| 绝对化用语 | 最好、第一、100%、永久等，替换 |
| 未经证实的对比 | "比 XX 好"需要真实证据，否则删除 |
| 他人商标、IP、音乐 | 不得出现他人商标；音乐需要授权 |
| 出镜授权 | 达人或其他出镜人须书面同意，广告用途须额外确认 |
| 危险演示 | 安全画面、儿童与食品化妆品类的特别要求 |
| 价格与承诺 | 只用用户确认的价格和活动 |

只做风险提示，不做法律结论。高风险项提醒用户找合规人员确认。

## 爆款参考
（第 2 节表格；没有数据写"没有数据"）

- 时长 / 人设 / 卖点顺序
- 开头 3 秒钩子
- 分镜表
- 结尾行动号召

## 脚本 B
（同上）

## 脚本 C（如适用）
（同上）

## 发布文案与标签
（第 4 节）

## 拍摄清单
（第 5 节）

## 合规检查
（第 6 节；没有问题写"未发现明显风险项"）

## 8. 人工确认点

1. 卖点和宣称由用户确认。没确认的不能写进脚本。
2. 深挖 FastMoss（第二轮）前问用户，说明会消耗额度。
3. 用户选定版本后，才细化分镜、字幕和口播。
4. 发布文案和标签由用户确认后才算完成。

## 9. 失败与异常处理

- FastMoss 未连接或额度不足：脚本照写，爆款参考部分写"没有数据"，说明缺口。
- 视频结果为空：换关键词或类目重搜一次；仍为空就写"没有数据"，不要编造同类视频。
- 视频数据不完整（缺播放或互动）：只列出有的指标，缺的写"没有数据"。
- `video_script_info` 返回为空：只分析画面结构，注明"无口播文本数据"。
- 用户要求"照着某个视频拍一样的"：拒绝逐句或逐镜复制，改为提炼结构，并给出原创的台词和画面。
- 不编造播放量、转化率、达人佣金或爆款承诺。所有数字必须来自工具结果，并写明工具和时间范围。
