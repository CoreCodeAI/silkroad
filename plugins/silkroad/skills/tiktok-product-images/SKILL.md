# TikTok Shop 主图与详情图

> **TikTok 数据来源**：下文写的是 FastMoss 工具。`silkroad_status` 显示 FastMoss 没连上、Kalodata 为 `configured` 时，改用 Kalodata：按 `kalodata-data` 技能第 5 节的对照把每一步换成 `silkroad_kalodata_*` 工具，费用控制和口径照那个技能；Kalodata 没有对应的数据写"没有数据（Kalodata 不提供）"。两个都连上时默认用 FastMoss，用户指定时听用户的；两个都没有时才按本技能的降级方式处理。

为商品做商品卡主图（1:1）和详情页图。可以只出规划和提示词；图片生成服务已配置时，再按批准的规划生成并逐张检查。

## 0. 确认输入

- **必需**：目标站点和语言；商品事实和卖点（用户确认过的）。
- **强烈建议**：用户的商品实拍图，给出绝对路径。
- **可选**：品牌色、风格偏好、想突出的卖点顺序、张数。

实拍图处理：

- 路径必须是绝对路径，并确认文件存在。不存在就请用户给正确路径。
- 没有实拍图时只能做概念图。必须明确告诉用户：概念图不能当作实物图使用，不能放在商品卡或详情页里冒充真实商品外观。用户仍要做，就只做规划和提示词，并在每张图的说明里标注"概念图，非实物"。
- 实拍图的颜色、形状、结构、配件、数量是唯一的外观依据。用户没说的外观细节不要自己补。

## 1. 检查能力

调用 `silkroad_status`。

- 图片生成服务（image provider）为 configured：可以生成。
- 图片生成服务缺失（missing）：只交付规划、提示词和检查清单，并告诉用户：打开左侧 SilkRoad 面板，在图片生成服务下填写 key 并保存（不要在对话里索要或粘贴 key），保存后再检查一次。
- FastMoss 未 connected：竞品对标和买家关注点无法获取。继续做规划，注明"未做竞品视觉对标"。

## 2. 竞品视觉对标（便宜的先做）

1. 类目名称先用 `mcp__fastmoss__search_category_by_words` 换成类目 ID。
2. `mcp__fastmoss__product_rank_top_selling` 取同类头部商品 3–5 个。
3. `mcp__fastmoss__product_detail_info` 查这几个商品的基础信息和图片字段。
4. `mcp__fastmoss__product_review_list` 取一页买家评价，归纳买家关注点，用来决定副图的卖点顺序。

输出对标表：

| 竞品 | 主图构图 | 背景与光线 | 图上文字 | 卖点呈现方式 | 可差异化的地方 |
|---|---|---|---|---|---|

规则：

- 只对标结构和风格，不下载、不复用、不改造竞品的图片或文字。
- 图上文字的写法不照抄竞品的文案。
- 数据缺失写"没有数据"。

工具参数名以连接后实际返回的工具 schema 为准。

## 3. 图片规划（生成前必须用户确认）

规划为主图 1 张 + 副图 4–6 张（数量可由用户调整）。每张图写清楚用途，用途只能从下面几类选：

- 展示外观（整体、正面、多角度）
- 讲一个卖点（一图一个卖点）
- 尺寸对比（配参照物，比例要真实）
- 使用场景（真实使用的情境）
- 包装清单（列出用户确认的配件）
- 细节特写（材质、做工、接口）
- 售后或保障（只在用户提供政策时使用）

规划表：

| 序号 | 用途 | 画面说明 | 图上文字（站点语言） | 依据（卖点或买家关注点） | 需要的实拍图 | 能否生成 |
|---|---|---|---|---|---|---|

尺寸和格式：

- 主图比例按 1:1 规划。
- 具体像素、文件大小、格式、详情图尺寸，以 TikTok Shop 当前官方规则为准。写在输出里时统一注明："请以 TikTok Shop 当前官方规则为准，发布前核对。"
- 不要在对话里写死像素数字，除非已在本次会话中从官方来源核实。

生成前问用户三件事：张数、尺寸（或按规划默认）、每张要几个备选（`n`）。说明生成会花费用，建议先出少量样张。

## 4. 提示词

每张图给英文提示词和中文说明：

```
### 图 2：尺寸对比
- 用途：展示尺寸，帮助买家判断大小
- 中文说明：商品放在桌面，旁边放一个常见参照物（例如水杯），比例真实
- 英文提示词：<写清主体=参考实拍图中的商品，背景，光线，机位，留白位置>
- 图上文字（站点语言）：<仅保留 1–3 个词或数字，拼写由用户核对>
- 参考图：/绝对路径/实拍图.jpg
- 尺寸：1024x1024（主图）或 1024x1536（详情图）
- 张数 n：1（首轮）
```

提示词必须包含的约束（每张都写）：

- 商品外观与参考实拍图一致，不改颜色、形状、结构、配件数量。
- 不出现他人商标、他人 IP 角色、名人肖像。
- 不出现伪造的认证标志（如 CE、FDA、有机认证等，除非用户提供了证据）。
- 不做夸大的效果对比（如"使用前后"式对比、虚假的测试数据）。
- 不出现医疗或功效图示。
- 文字使用目标站点语言，拼写正确，数量少。文字内容必须是用户确认过的。
- 不出现站外联系方式、二维码或其他平台引流元素。

价格、促销字样是否允许，以 TikTok Shop 当前官方规则为准；默认不要在图上放价格。

## 5. 生成（需要批准，并且服务已配置）

调用 `silkroad_generate_image`：

- `prompt`（必需）：第 4 节的英文提示词。
- `size`：如 `1024x1024`（主图）、`1024x1536`（竖图详情）。
- `n`：1–4。首轮用 1，方向确认后再加量。
- `reference_images`：实拍图的绝对路径数组。**有实拍图时必须传**，这是让生成结果贴近真实商品的依据。
- `output_dir`（可选）：绝对路径目录。建议按商品建一个子目录，例如 `<项目>/images/<商品名>/`。

执行规则：

- 每张图单独调用，便于出问题时只重做那一张。
- 不要一次跑完所有图。先出主图和 1–2 张副图，用户看过方向后再继续。
- 返回的保存路径要原样告诉用户。没有返回文件路径就不要说"已生成"。
- 同一张图重做最多 2 次。仍不合格时，说明卡在哪里，请用户决定是换参考图、改规划还是放弃。

## 6. 逐张检查

每张生成图都过一遍：

| 检查项 | 通过标准 | 结果 |
|---|---|---|
| 外观一致 | 颜色、形状、结构、配件数量与实拍图一致 | 通过 / 重做 / 人工判断 |
| 比例 | 没有明显拉伸、变形，尺寸对比的参照物比例合理 | |
| 文字 | 清晰、拼写正确、语言是站点语言，内容与用户确认的一致 | |
| 商标与 IP | 没有他人商标、角色、名人形象 | |
| 认证标志 | 没有未经证实的认证或资质标志 | |
| 效果描述 | 没有夸大对比、虚假数据、医疗或功效图示 | |
| 平台元素 | 没有站外引流、二维码，价格或促销字样按当前规则处理 | |
| 生成瑕疵 | 没有多余的手指、错误的配件、乱码字符 | |

结论只有三种：通过、重做（写明原因和要改的提示词部分）、需要人工判断。检查结论必须对应到具体文件路径。

## 7. 输出模板

```
## 结论
规划 1 张主图 + 5 张副图；已生成 3 张，2 张通过、1 张需重做。

## 竞品视觉对标
（第 2 节表格；无数据写"没有数据"）

## 图片规划
（第 3 节表格）

## 提示词
（第 4 节，每张一段）

## 生成结果
| 图 | 文件路径 | 检查结论 | 备注 |
|---|---|---|---|

## 待确认
- 缺少的实拍图或商品参数
- 图上文字需要用户核对
- 尺寸和规则以 TikTok Shop 当前官方规则为准

## 建议下一步
- 用户挑选通过的图
- 重做项的修改方向
- 需要时进入 tiktok-listing-seo 或 tiktok-video-script
```

若没有生成（服务未配置或用户未批准），"生成结果"一节写"未生成"，并给出开启方式。

## 8. 人工确认点

1. 规划确认后再生成。每次批量生成前都要确认一次。
2. 用户从结果里挑选；不合格的按第 5 节规则重做。
3. 没有实拍图的概念图，用户必须确认"仅用于规划，不作为实物展示"。
4. 图上文字在生成前由用户确认内容。

## 9. 失败与异常处理

- 图片生成服务未配置：交付规划、提示词和配置指引，不要尝试调用生成工具。
- 生成工具报错或超时：如实报告错误。最多重试一次，并调整提示词或尺寸，不要反复刷量。
- 实拍图路径不是绝对路径或文件不存在：请用户提供正确路径，不要猜测路径。
- 生成结果外观与实拍不符：不交付，标记重做，并说明偏差点。
- 竞品图无法获取：写"没有数据"，不要推断竞品构图。
- 用户要求加入他人品牌、认证标志或夸大对比：拒绝该元素，给出替代方案，说明原因。
- 不要编造商品的材质、颜色或功能来填充画面。用户没说的，先问。
