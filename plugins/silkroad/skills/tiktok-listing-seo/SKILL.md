# TikTok Shop 标题与描述（Listing SEO）

> **TikTok 数据来源**：下文写的是 FastMoss 工具。`silkroad_status` 显示 FastMoss 没连上、Kalodata 为 `configured` 时，改用 Kalodata：按 `kalodata-data` 技能第 5 节的对照把每一步换成 `silkroad_kalodata_*` 工具，费用控制和口径照那个技能；Kalodata 没有对应的数据写"没有数据（Kalodata 不提供）"。两个都连上时默认用 FastMoss，用户指定时听用户的；两个都没有时才按本技能的降级方式处理。

为一个已上架或准备上架的 TikTok Shop 商品写或改标题、描述、关键词和属性建议。文案只能建立在用户确认过的商品事实上，竞品和搜索数据只用来决定"怎么写得更容易被搜到"，不用来编事实。

## 0. 确认输入

开始前确认下面的信息，缺什么问什么：

- **必需**：目标站点和语言（如 US、GB、ID、TH、MY、VN、PH、SG、MX）。用户没说就问，不要默认。
- **必需**：商品事实。至少包括名称、规格、材质、尺寸、颜色、数量、适用人群、核心卖点、包装清单、售后政策。
- **或者**：已上架商品的链接或 product_id（用来读现有标题和详情）。
- **可选**：品牌名、禁用词、想要的风格（专业 / 亲切 / 促销感）。

商品事实一律以用户为准。用户没给的参数（比如防水等级、电池容量、认证编号）不要补写，列进"待确认"。

## 1. 检查数据源

调用 `silkroad_status`，不要凭印象判断连没连上。

- FastMoss（工具前缀 `mcp__fastmoss__`）未 connected：告诉用户本场景需要它来看竞品标题和买家用语。继续用用户事实写文案，并在输出里注明"未做竞品对标"。
- SerpApi 未 configured：跳过站外搜索词，注明"没有站外搜索数据"。
- 两者都缺也能交付：标题和描述仍可写，但关键词表只能来自用户给的事实，要明确标注。

## 2. 分阶段取数（便宜的先做）

FastMoss 按调用计费，按下面顺序做，每一步拿到结果后先看结论再决定要不要下一步。

第一轮（约 4–5 次调用）：

1. 类目名称换类目 ID：`mcp__fastmoss__search_category_by_words`。用户已经给了类目 ID 就跳过。
2. 商品基础信息：`mcp__fastmoss__product_detail_info`，查自家商品（有 ID 时）或 1–2 个竞品。拿到现有标题、价格、类目、评分。
3. 同类头部标题：`mcp__fastmoss__product_rank_top_selling` 取一页（10–20 条），只看标题和销量。
4. 核心词搜索：`mcp__fastmoss__product_search`，用核心词取 10–20 条，看标题用词分布。
5. 平台规则：`mcp__fastmoss__search_fastmoss_documents` 和 `silkroad_web_search`，查当前标题和描述的规则。

第一轮结束后，先给用户一版初步关键词清单，问要不要继续：

第二轮（用户同意后）：

6. 买家用语：`mcp__fastmoss__product_review_list` 取一页，归纳高频词、好评词、抱怨点。
7. 站外搜索词：`silkroad_serpapi_search`，engine 用 `google`（搜索建议）或 `google_trends`（趋势）。仅在 SerpApi 已配置时使用。

查额度可用 `mcp__fastmoss__credit_usage_summary`（无参数）。

工具参数名（如 `filter.region`、`filter.product_id`、`page`、`pagesize`）以连接后实际返回的工具 schema 为准，不要凭记忆填。

## 3. 关键词表

把所有关键词放进一张表，每个词都要写来源：

| 类型 | 关键词 | 来源 | 数据（有则填） | 建议用于 | 备注 |
|---|---|---|---|---|---|
| 核心词 | | 竞品标题 / 用户事实 | 出现次数 | 标题前段 | |
| 属性词 | | 用户事实 | | 标题中段、属性 | |
| 场景词 | | 买家评价 / 站外搜索 | | 描述 | |
| 长尾词 | | 站外搜索 | 搜索热度 | 描述 | |
| 买家用语 | | 商品评价 | 出现次数 | 描述卖点 | 只保留与商品事实一致的说法 |

规则：

- 没有数据的单元格写"没有数据"，不要估一个数。
- 关键词必须和商品事实一致。买家常搜"waterproof"，但用户没确认防水，就不能进标题。
- 不堆砌。同一个词在标题里出现两次以上没有意义，也会影响可读性。

## 4. 标题方案（3 个）

给 3 个版本，每个注明侧重和字符数：

- 版本 A：搜索覆盖型，尽量放核心词和属性词。
- 版本 B：点击吸引型，突出一个最强卖点和使用场景。
- 版本 C：简洁型，去掉修饰，只留品类、关键属性和规格。

写法的通用骨架（不是硬性模板）：品牌（可选）+ 核心品类词 + 关键属性（材质 / 规格 / 数量）+ 场景或人群。

标题长度上限和格式以 TikTok Shop 当前官方规则为准，写作时不要凭记忆写死字数。在输出里统一写："标题长度上限请以 TikTok Shop 当前官方规则为准，发布前在后台核对。"

字符数的计算方式按目标站点语言计；英文按字符数（含空格）计，并标明"计数方式：字符（含空格）"。

## 5. 商品描述

顺序固定为：**卖点 → 规格参数 → 使用场景 → 包装清单 → 售后说明**，用目标站点语言写。

- **卖点**：每条卖点后面标注依据，格式为"（用户确认）"或"（待确认）"。待确认的卖点不能进入终稿。
- **规格参数**：用表格，数据全部来自用户。缺的写"待补充"。
- **使用场景**：可以提出建议，但要标注"（建议，非商品事实）"。
- **包装清单**：只写用户确认的内容。
- **售后说明**：只写用户给的政策（退换天数、保修期等）。不知道就写"待补充"，不要写平台默认值。

描述里不写买家评价的原话，也不写竞品的卖点原文。用买家用语的意思，用自己的话表达。

## 6. 属性填写建议

平台类目属性以后台实际表单为准。本场景只给建议值，表格如下：

| 属性名 | 建议值 | 依据 | 是否必填 |
|---|---|---|---|
| | | 用户事实 / 竞品常见值（标明） | 以后台为准 |

没有依据的属性不要硬填，留空并标注"待确认"。

## 7. 合规检查

逐条扫描标题、描述、属性，把可能有问题的说法列出来：

| 原文片段 | 风险类型 | 建议替换 | 严重度 |
|---|---|---|---|
| | 绝对化用语（最好、第一、100%、永久、根治） | 换成可证实的描述 | 高 |
| | 医疗或功效宣称（治疗、消炎、减肥、美白效果） | 删除，或改为外观和使用描述 | 高 |
| | 未经证实的认证或资质（CE、FDA、有机、环保认证等，用户未提供证据） | 删除 | 高 |
| | 他人品牌词或 IP（别人的商标、型号兼容的品牌名） | 删除，仅保留"适配 / 兼容"且需用户确认 | 高 |
| | 比较类宣称（"比 XX 更好"） | 改为描述自身参数 | 中 |
| | 价格或促销承诺（最低价、限时必降） | 删除，除非用户确认活动 | 中 |
| | 虚假数量或库存、夸大销量 | 删除 | 高 |

规则：

- 只做风险提示，不做法律结论。高风险项提醒用户找合规人员确认。
- 所有"高"风险项必须在终稿前处理掉，不能留给用户自己发现。
- 合规检查的依据是通用原则和平台当前规则，不要引用未核实的具体条款编号。

## 人工确认点

1. 商品事实确认之后才写描述。用户没确认的参数，只能列进"待确认"。
2. 用户从 3 个标题里选 1 个（或指定组合）。
3. 深挖 FastMoss（第二轮）前问用户，说明会消耗更多额度。
4. 终稿由用户确认后才算完成。告诉用户发布前在 TikTok Shop 后台核对字数和规则。

## 失败与异常处理

- FastMoss 未连接、额度不足或工具报错：说明缺的是什么、影响哪部分，其余照常完成。不要因此停止整个任务。
- 工具返回为空：写"没有数据"，不要推断竞品情况。
- 用户要求写"最好""第一""包治"之类：给出替代写法，并说明原因。
- 用户事实之间有冲突（例如用户说 500ml，现有详情页写 480ml）：列出冲突，请用户决定，不替用户选。
- 不编造数字。销量、评分、好评率、搜索量只能来自工具结果，并写明工具和时间范围。
- 不要把竞品标题原样拼接或轻微改写成自己的标题。标题应从关键词和商品事实重新组织。
