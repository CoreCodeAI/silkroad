# 评论与差评洞察（TikTok Shop）

> **TikTok 数据来源**：下文写的是 FastMoss 工具。`silkroad_status` 显示 FastMoss 没连上、Kalodata 为 `configured` 时，改用 Kalodata：按 `kalodata-data` 技能第 5 节的对照把每一步换成 `silkroad_kalodata_*` 工具，费用控制和口径照那个技能；Kalodata 没有对应的数据写"没有数据（Kalodata 不提供）"。两个都连上时默认用 FastMoss，用户指定时听用户的；两个都没有时才按本技能的降级方式处理。

目标：从买家评论里找出满意和不满意的主题，判断根因，给出按影响排序的改进清单。可选做竞品对比和回复话术草稿。

所有结论必须来自真实评论。样本不足时写明，不要用推测补足。

## 0. 硬规则

- 不编造评论，不估算数字。没有的数据写「没有数据」。
- 不建议或协助诱导好评、刷好评、用赠品或折扣换评价（平台禁止）。不建议删除或要求删除差评。
- 公开回复差评只起草，由用户确认后自己发布。草稿不争辩、不索要联系方式、不承诺规则里没有的补偿。
- 输出中的买家昵称和其他个人信息要去掉，只保留评论内容。

## 1. 确认输入

- 商品（必需，三选一）：自己店铺的商品 ID（可用 `silkroad_tts_products` 的 `product_id` 核对）；竞品商品 ID 或链接；用户导出的评论文件或粘贴的评论文本。
- 站点（用户没说就问）。
- 可选：竞品 1 到 3 个、时间范围、只看差评（1–3 星）。

## 2. 选择数据源

1. 调用 `silkroad_status` 查看 FastMoss 是否已连接。
2. FastMoss 已连接：用 `mcp__fastmoss__product_review_list` 分页拉取评论。参数以连接后返回的工具 schema 为准，尽量覆盖足够样本。
3. 先拉第一页，再调用 `mcp__fastmoss__credit_usage_summary` 查看额度，告诉用户已用和剩余，再决定要不要继续翻页。
4. 商品基本信息（评分、店铺、价格）用 `mcp__fastmoss__product_detail_info`。
5. FastMoss 未连接：告诉用户这个场景需要 FastMoss 的评论数据，请在左侧栏「跨境电商」面板的「数据源」里连接。在此之前，可以用用户自己的评论文件继续做。竞品对比做不了，要说明原因。不要向用户索要 API key。
6. 用户的评论文件：Seller Center 导出的 Excel 先转成 CSV。列名不明确时，先列出表头，请用户指出哪一列是评论内容、星级、时间和语言。

## 3. 记录样本

每次分析都先写样本说明：
- 样本量、数据来源（FastMoss 或用户文件）、时间范围。
- 星级分布（1–5 星各多少条）。
- 语言分布（大致即可）。

判断可靠性：
- 少于 30 条：结论开头必须写「样本不足 30 条，结论不可靠，仅供参考」。
- 0 条：停止分析，说明原因，建议换商品或扩大时间范围。

## 4. 理解与归类

先按评论原语言理解含义，再归到中文主题。一条评论可能命中多个主题。

好评主题的参考分类：效果或功能、外观、手感或材质、性价比、包装、送礼、物流速度、客服。

差评主题的参考分类：质量或做工、尺码或规格不符、与描述不符、物流破损、物流慢、使用困难或说明不清、性价比低、包装问题、客服响应、其他。

每个主题给出：
- 次数：提到该主题的评论条数。
- 占比：次数 ÷ 样本总条数。注明一条评论可能属于多个主题。
- 代表原话：最多 3 条，保留原文，附中文翻译，去掉个人信息。

## 5. 区分根因

对每个主要差评主题，判断根因类别，并写出依据（哪几条评论支持这个判断）：
- 产品问题：做工、材质、功能本身的缺陷。
- 描述问题（期望管理）：实物与标题、图片或详情不符，买家期望过高。
- 物流问题：运输破损、时效慢、包装不足以保护商品。
- 客服问题：回复慢、处理不当。
- 无法判断：证据不足，写明需要什么额外信息。

## 6. 竞品对比（可选）

- 对同一主题，列出各商品的占比，并写出每个商品的样本量。
- 样本量差距大时，占比只作参考，要说明。
- 对手的明显短板，就是我们的机会点。写成具体的差异化方向，不写成空话。

## 7. 建议

按影响排序（次数 × 严重程度）。每条建议都要写出依据和负责方。

- 产品与供应链：具体修改点，写给采购或工厂，例如哪个尺寸、哪道工序、哪种包装。
- Listing 修改：补充说明、尺码表、图片要展示什么。可交给 `tiktok-listing-seo` 技能继续做。
- 客服话术：针对高频差评的标准回复草稿。用户同意后，可存入 `~/SilkRoad/knowledge/replies/`，智能体只在用户同意后写入。
- 公开回复差评的草稿：用评论的语言写，先感谢或致歉，再说明处理方式。涉及补偿时，只能用 `policies/` 里有的内容。

## 9. 人工确认点

- 样本少于 30 条：必须明确提示结论不可靠。
- 翻页深入或竞品分析前：先报告额度，问用户是否继续。
- 公开回复差评：由用户确认后自己发布。
- 写入知识库 `replies/`：需用户同意。
- 不建议任何诱导好评、删除差评的做法。

## 10. 降级与边界

- FastMoss 未连接：按第 2 节处理。不能给竞品数据，也不能给自家商品的全平台样本。
- 星级字段缺失：写「没有星级数据」，不要从文字里推断星级后当作事实。
- 评论内容为空或极短：这类条目不计入主题统计，单独说明数量。
- 用户粘贴的少量文字：可以做定性归纳，但必须标注样本量很小。
- 只分析评论。不修改 Listing、价格或商品，也不调用写操作。
- 不对买家个人做识别，不输出个人信息。
