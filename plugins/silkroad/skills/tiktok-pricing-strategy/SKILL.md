# 定价策略（TikTok Shop）

> **TikTok 数据来源**：下文写的是 FastMoss 工具。`silkroad_status` 显示 FastMoss 没连上、Kalodata 为 `configured` 时，改用 Kalodata：按 `kalodata-data` 技能第 5 节的对照把每一步换成 `silkroad_kalodata_*` 工具，费用控制和口径照那个技能；Kalodata 没有对应的数据写"没有数据（Kalodata 不提供）"。两个都连上时默认用 FastMoss，用户指定时听用户的；两个都没有时才按本技能的降级方式处理。

目标：给一个商品定上架价、首发活动价和长期价，并检查利润能不能撑住平台费用、达人佣金和广告。结论放最前，利润表和公式紧跟其后。

## 0. 先确认输入

必需：
- 商品：商品 ID、链接，或文字描述。
- 站点。用户没说就问。
- 单件到手成本 C（采购 + 头程 + 包装），用站点本币。

可选：尾程/履约费 F、平台佣金率、支付手续费率、目标毛利率、计划达人佣金率、广告预算、退货率、退货回收率、退货处理费。

缺了哪些费率，合成一句话问一次。例如："还缺尾程费、平台佣金率、支付手续费、计划达人佣金率、退货率。有就告诉我实际值；不知道的我会用标注为【假设】的数值继续算，你之后再替换。另外请确认售价是否含税。"

## 1. 费率来源规则（必须遵守）

- 每个费率只能来自三处：用户提供、官方来源（你用 `silkroad_web_search` 找到官方页面并实际抓取过，才算）、或你设定的假设值。
- 平台佣金率、支付手续费率不能当作事实陈述。没有用户提供或官方抓取时，一律写成【假设】。
- 假设值在每个表格里都要醒目标注。结论里附敏感性：费率每变动 1 个百分点，单件利润变化 = 净收入 R × 0.01。
- 给出假设清单，每项写明值、来源（用户 / 官方 / 假设）。
- 税费：确认售价是否含税。不确定时，明确写"按不含税计，需核对"。

## 2. 第一步：竞品价格带和佣金（先做廉价查询）

阶段一（直接做）：
1. `mcp__fastmoss__market_category_analysis`，analysis_type=price_distribution，近 28 天，取类目价格分布。
2. `mcp__fastmoss__product_search`，按价格区间筛选（区间由类目分布推出），取销量前 20。用 GMV 加权算价格带。
3. `mcp__fastmoss__product_detail_info`：前 5 个竞品，取价格、店铺、评分。

阶段一结束后：给出价格带初步结论，并标注还缺什么。然后停下，先调用 `mcp__fastmoss__credit_usage_summary`，问用户是否继续。

阶段二（需同意）：
- `mcp__fastmoss__product_sku`：前 3 个竞品的 SKU 价格和销量占比。
- `mcp__fastmoss__product_creator_analysis`：前 3–5 个竞品。佣金率范围只在返回字段里有佣金时才能用；没有就写"没有数据"。
- `mcp__fastmoss__product_investment`：前 3–5 个竞品的广告投入和 ROAS。竞品每单广告成本的估算 = 广告花费 ÷ 同期成交单数，标注为估算。

工具参数名以连接后实际返回的工具 schema 为准。

## 3. 第二步：利润测算（核心表）

### 符号

| 符号 | 含义 | 来源 |
|---|---|---|
| P | 售价（买家支付价，含税口径需确认） | 候选价 |
| C | 单件到手成本（采购 + 头程 + 包装） | 用户 |
| F | 每单尾程/履约费（按送达单计） | 用户或【假设】 |
| r | 退货率 | 用户或【假设】 |
| s | 退货商品可回收比例（能二次销售部分，按货值） | 用户或【假设】 |
| F_ret | 每次退货的处理和逆向物流费 | 用户或【假设】 |
| c_plat | 平台佣金率 | 用户、官方或【假设】 |
| c_pay | 支付手续费率 | 用户、官方或【假设】 |
| c_aff | 达人佣金率（计划值） | 用户或计划 |
| A | 每单广告分摊 | 用户预算 ÷ 计划单量，或【假设】 |
| π | 每单目标净利润 | 默认 0 |
| f | f = c_plat + c_pay + c_aff | 派生 |

记账假设（需用户确认）：退货整单全额退款；平台佣金、支付手续费按退款后的净收入 R 计算。

### 单件利润瀑布表（每个候选价一列）

| 行 | 项目 | 公式 | 候选价 1 | 候选价 2 | 候选价 3 |
|---|---|---|---|---|---|
| 1 | 售价 | P | | | |
| 2 | 退货退款 | −P × r | | | |
| 3 | 净收入 R | P × (1 − r) | | | |
| 4 | 商品成本 | −C × (1 − r × s) | | | |
| 5 | 毛利 | 行3 + 行4 | | | |
| 6 | 毛利率 | 行5 ÷ R | | | |
| 7 | 尾程/履约 | −F × (1 − r) | | | |
| 8 | 退货处理 | −F_ret × r | | | |
| 9 | 平台佣金【假设】 | −R × c_plat | | | |
| 10 | 支付手续费【假设】 | −R × c_pay | | | |
| 11 | 达人佣金（计划） | −R × c_aff | | | |
| 12 | 广告分摊【假设】 | −A | | | |
| 13 | 净利润 | 行5 + 行7 到 行12 之和 | | | |
| 14 | 净利率 | 行13 ÷ R | | | |

行 4 的推导：每单发出一件，成本 C；退货的那部分 r，只回收 s 比例的货值，所以期望成本是 C(1 − r) + C·r(1 − s) = C(1 − r·s)。

### 盈亏平衡公式

以下公式和上表一致（代入 R = P(1 − r)，f = c_plat + c_pay + c_aff）：

- 广告前利润 X0 = P(1 − r)(1 − f) − C(1 − r·s) − F(1 − r) − F_ret·r
- 单件净利润 = X0 − A
- 盈亏平衡价（净利润 = 0）：P* = [C(1 − r·s) + F(1 − r) + F_ret·r + A] ÷ [(1 − r)(1 − f)]
- 目标利润 π 的最低可接受价：P_π = [C(1 − r·s) + F(1 − r) + F_ret·r + A + π] ÷ [(1 − r)(1 − f)]
- 给定价格 P 下，最高可承受达人佣金率：c_aff_max = [R(1 − c_plat − c_pay) − C(1 − r·s) − F(1 − r) − F_ret·r − A − π] ÷ R
- 广告分摊上限（每单）：A_max = X0 − π；按净收入计的 ACoS 上限 = (X0 − π) ÷ R

注意：f 里的 c_aff 要用计划值。如果用 c_aff_max 作为结论，要说明它是在"不推翻其他假设"的前提下算出的。

### 示例（数值全部为演示用的【假设】）

P = 30，C = 10，F = 3，F_ret = 4，r = 5%，s = 50%，c_plat = 8%【假设】，c_pay = 2%【假设】，c_aff = 10%（计划），A = 2。

- R = 28.5，商品成本 = 9.75，毛利 = 18.75，毛利率 65.8%
- 尾程 2.85，退货处理 0.20，平台 2.28，支付 0.57，达人 2.85，广告 2.00
- 净利润 = 8.00，净利率 28.1%
- 校验：X0 = 28.5 × 0.80 − 9.75 − 2.85 − 0.20 = 10.00，减 A = 8.00，一致。
- P* = 14.80 ÷ 0.76 ≈ 19.47
- 在 P = 30、π = 0 时，c_aff_max = (28.5 × 0.90 − 9.75 − 2.85 − 0.20 − 2.00) ÷ 28.5 ≈ 38.1%

## 4. 第三步：推荐价格

1. 候选价取 3–5 个，覆盖价格带的中位数附近和两侧。
2. 每个候选价都跑一遍瀑布表。剔除净利润低于 π 的候选。
3. 推荐三档价格：
   - 上架价：在价格带内，净利润达到目标。
   - 首发活动价：上架价打折后的价格。必须在活动折扣和活动佣金（如有）下仍然 ≥ P_π。活动规则以用户提供或官方为准，不能假设。
   - 长期价：广告预算收紧后仍能达到目标利润的价格。
4. 每档给出理由：价格带位置、竞品价格和销量、利润结果、风险。

## 5. 第四步：测价计划

- 先用中档上架价测试，首发活动价按计划启用。
- 观察指标：转化率、退货率、ACoS、单件净利润，以及竞品价格变化。
- 样本量：每个价格累计至少 50–100 单再判断（启发式，不是统计标准）。
- 调整触发（默认，用户可改）：
  - 单件净利润连续为负：先降低广告或佣金，再考虑调价。
  - 转化率明显低于竞品：测试下调 5%–10%，并观察 1–2 周。
  - 退货率高于假设：先查差评和退货原因，不要直接降价。
- 每次调价只改一个变量，并记录日期。

## 7. 人工确认点

- 开始前：成本、费率、是否含税。费率由用户提供，或用官方来源确认；否则用【假设】并标注。
- 第一阶段后：是否进入第二阶段深挖，先报额度。
- 推荐价格：由用户最终决定。
- 活动规则：首发活动价以用户确认的活动条件为准。

## 8. 失败与降级

- FastMoss 未连接：不能给竞品价格带和佣金数据。只能让用户提供竞品价格，或用 `silkroad_web_search` 找公开价格（标注来源和日期）。利润测算仍可做，但全部费率需要用户提供或标注假设。
- 佣金字段不存在或为空：写"没有数据"，不要用 0 代替。
- 广告投入数据为空：写"没有数据"，A 用预算或假设。
- 成本缺失：不做利润测算，只给价格带和竞品分析。
- 费率全部缺失：可以算，但结论前面必须写明"整体为假设结果，不可直接用于定价"。

## 9. 边界

- 只做价格和利润测算，不写文案，不选品。
- 不把平台费率、佣金政策当作事实陈述，除非有用户提供或官方来源。
- 不替用户决定最终价格。
